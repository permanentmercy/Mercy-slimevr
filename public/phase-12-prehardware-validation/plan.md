# Phase 12：无实机影子推理、回放与算法离线复验

> **复核状态：未通过整体验收。** S0 契约 6 项、S1 推理 5 项、S2 回放 2 项 Kotlin 测试均在本机通过；最新 S2 将 108,000 个逻辑帧逐帧送入 ONNX，组装加推理 P95 为 1.056 ms。S1 仍缺 VRServer 关闭时释放 Session 的调用，S2 未测完整 `VRServer.tick()` 且无内存门限；A1 静态门禁硬编码为通过且输入角速度语义不匹配；A2 复用旧 FinalConfirm，结果只属探索。验收证据与待办见 [results.md](results.md)。

## 目标与边界

在缺少实机数据期间，完成两类可验证工作：

1. SlimeVR Kotlin 服务端能用真实 ONNX Runtime 执行单帧流式模型，输入契约与 Python 一致，回放中安全处理状态、丢包与错误，并报告服务端侧延迟。
2. Phase 9 慢偏航和 Phase 11 快 Swing 的合成实验能区分算法收益与理想化注入造成的收益；短时评测不再以真值 Oracle 代替 P9 在线估计。

本阶段不采集或伪称实机数据，不把合成模型门禁称为硬件验收，不扩展网络容量，也不允许候选输出修改 Tracker 或 Avatar。实机影子和在线修正仍留给 Phase 8 后续计划。

## 代码审查基线

本计划基于 2026-10-18 的仓库审阅：

- [`CorrectorBridge.kt`](../../server/server/core/src/main/java/dev/slimevr/tracking/processor/corrector/CorrectorBridge.kt) 已挂入服务端采样路径，但 `executeInference()` 尚未运行模型；`applyCorrectionToTrackers()` 只计算局部变量，候选结果没有进入求解器。
- Bridge 的下肢 6D 旋转通道顺序与 [`contract_v2.py`](../../ai_corrector/corrector/contract_v2.py) 不一致：当前写入重复了 `colY.y`，漏掉 `colX.y`。下肢 14D 契约还要求角加速度和角速度；当前代码把线加速度写入角加速度通道，并把角速度全置零。
- SlimeVR 的协议结构有可选 `rawAngularVelocity` 字段，但当前 `Tracker`/`DataFeedBuilder` 路径没有把它提供给 `CorrectorBridge`。必须核对数据来源与时间戳；不得把缺失值或线加速度伪装成陀螺数据。
- 服务端 `server:core` 当前未声明 ONNX Runtime 依赖。Python [`export.py`](../../ai_corrector/corrector/export.py) 导出通用 `Corrector`；它没有包含 Phase 11 的世界系 Yaw-Neutral 投影。Phase 11 checkpoint 不能直接当成已兼容的 ONNX 模型。
- 配置默认模型路径为 `ai_corrector/checkpoints/best/cstn_best.onnx`，需要确认路径、文件来源和实际模型 ABI。已有 artifacts 中的 smoke 模型/权重受 `.gitignore` 忽略，只能作为本地实验输入，不能假设新 checkout 中存在。

## 执行顺序

### S0：冻结输入契约与模型 ABI

1. 对照 Python 合成器、`contract_v2.py`、SlimeVR `Tracker` 更新路径和协议数据 feed，逐字段记录来源、单位、坐标系、时间戳、滤波/重置语义和缺失策略。
2. 修正或明确下肢 6D 旋转列顺序。对角加速度、角速度和 age 字段作出可执行决定：优先接入确有来源的对应观测；若需从旋转差分推导，使用单调时间戳、因果差分和与训练数据一致的定义，并在契约中标为派生量；若训练/在线语义不能对齐，则先修改契约与数据生成，再运行精度评测。禁止填入错误物理量后继续称作契约通过。
3. 生成包含 8 路、每个字段取唯一哨兵值的固定 fixture，分别由 Python 和 Kotlin 组装；逐元素比对 124 维向量、valid/age、四元数顺序和旋转往返结果。
4. 选择模型测试对象并记录 SHA-256、输入/输出名称及形状、hidden/state 形状、训练/导出代码版本。先用可重建的工程 smoke 权重验证运行时线路；它只验收接口，不代表精度。Phase 11 模型必须有包含世界轴投影的专用导出 wrapper，并通过 PyTorch/ONNX 递归状态数值一致性检查后才可作为影子候选。

**S0 通过条件**：124 维字段有唯一且与训练一致的定义；缺失观测不会被误标成有效值；模型产物可定位、可重建或带哈希；对任一未对齐字段明确停在接口/精度门禁，不暗中补零放行。

### S1：实现真实 ONNX 影子推理

1. 为 `server:core` 增加并固定兼容的 CPU ONNX Runtime 依赖。模型 Session 在服务初始化时加载一次，关闭时释放；不得在 60 Hz 的 `tick()` 内反复创建 Session。
2. 按导出模型 ABI 传入 `[1,1,124]` 的 `x` 和因果状态 `h/c`，读取 `dq/gate/contact/hn/cn`。状态维度从已验证模型配置得出，不硬编码成与 checkpoint 不符的形状。
3. 每个有效样本更新候选残差、gate、contact 和状态；`resetState()`、全量/快速 reset、空间切换及 tracker 长时间断流必须清空递归状态。新会话第一帧行为应可复现。
4. 默认仅影子模式：记录模型版本、输入有效率、输出、门控、旁路原因和时延；不修改 tracker 姿态，不调用任何 Avatar 写入路径。模型缺失、输出 shape 错误、NaN/Inf、推理异常或超时均回退到原始服务端行为。
5. 增加可注入的推理接口/测试替身，避免单测依赖本机绝对模型路径；模型文件加载失败必须显式报告，不能假装已推理。

**S1 通过条件**：服务日志/测试能证明 ONNX 确实被调用且输入变化会产生可观察的候选输出；连续帧状态被传递，reset 后状态归零；故障旁路有效；影子模式下 Avatar/Tracker 原始姿态逐帧不变。

### S2：服务端确定性回放与性能验收

1. 让固定 fixture 穿过实际 Kotlin 特征组装和 Bridge 推理路径，与同一 ONNX/PyTorch 输入输出对照。单帧张量及递归输出容差沿用导出报告中已验证的容差，若需放宽必须解释来源。
2. 建立可重复的 60 Hz 合成回放：正常连续输入、胸/臂 VD 缺失、单路腿 tracker 缺失/过期、时间间隔跳变、快速/全量 reset、Session 加载失败和连续异常输出。
3. 至少跑完一段逻辑 30 分钟长度（108,000 帧）的连续流；实际运行时间可短于 30 分钟，但模拟时间必须由帧时间戳推进。检查状态内存有界、无 NaN/Inf、无跨 reset 状态泄漏。
4. 分别报告特征组装、ONNX 调用和 Bridge 处理的 P50/P95/P99、最大值、旁路计数与运行环境。开发机上端到端 Bridge P95 目标不超过 20 ms；这是开发环境性能门槛，不代表目标设备或实机网络延迟。

**S2 通过条件**：固定回放可复现；输入输出契约和 reset/丢失路径全部有自动测试；影子回放没有姿态写入；P95 达标，若不达标则定位耗时并保持本阶段未通过，不以 Python 单线程推理数替代服务端数字。

### A1：修正 Phase 9 合成物理与安全评测（可与 S1/S2 并行）

1. 将严格零漂、固定机体系偏置、白噪声、偏置随机游走和缓慢偏置变化分别建模；零漂用例必须同时关闭随机游走。先定义传感器运动、噪声/偏置注入、融合姿态生成的因果顺序，不能把“世界轴角度漂移”反投影后就称为真实陀螺偏置/AHRS 模型。
2. 运行时算法输入不得读取真值偏移、注入漂移率、未来帧或独立端点姿态。对静止门禁按每颗 tracker 分开验证；脚接触不作为大腿/小腿 ZARU 证据。没有裸陀螺输入时，将结果命名为“融合姿态残余漂移估计”并保留输入限制，不宣称硬件陀螺零偏校正。
3. 比较 Raw、ZARU-only、步态辅助-only、Full；覆盖严格零漂、正负常偏置、随机游走、静态姿势保持、持续运动/转身、无可信静止段和 VD 缺失。每个主要漂移场景至少 30 个独立种子/会话，压力场景至少 10 个；按 Phase 9 的会话终点定义报告四路 `D_raw/D_corr/G`、胜率、95% CI、单路和最差会话。
4. 零漂验收单独设置安全否决：在运行前冻结并逐会话报告每 tracker 的 endpoint 改变量；沿用现有项目门限，四路合计零漂 endpoint 变化不超过 0.05°，静态保持姿态增量不超过 0.10°。不能只看平均收益；若模型没有可靠证据，必须能保持直通/不更新。参数和门限只用开发/验证组选择，隔离组锁定后一次运行。

**A1 通过条件**：仿真假设和信号单位透明；无未来/真值泄漏；严格零漂与随机游走不混淆；非零偏置主场景的会话级收益 95% CI 下界大于零，且零漂与静态门禁满足上述上限。安全门禁由实测数字自动裁定。合成通过只表示该参数化仿真下通过，不等同实机有效。

### A2：重新评估 Phase 11 的 P6 增量价值

1. 先冻结新的 source-level/subject-level 隔离 manifest。当前 190 条 FinalConfirm 只按子集内文件序号隔离，不能重复用作调参后最终确认；若数据没有可靠 subject ID，明确降级为 source-level 隔离并说明范围。
2. 短时评测以**实际因果 P9 估计器**输出为基线，移除当前 oracle P9 Twist 基线。若当前 P9 估计器输入/状态不满足在线契约，报告为未通过前置条件，不用 oracle 成绩代替。
3. 对 VD/上身上下文做参数化噪声、时间延迟、丢帧、缺失和 tracker 安装偏差敏感性测试。没有实机标定时，这些仅为鲁棒性压力范围，不称作真实 VD 误差分布。
4. 对 Raw、P9-only、P6-only、P9+P6 同时报告世界 Swing 测地残差、零漂/静态保持误改、全姿态误差；用一致 SMPL-H 骨架映射计算 FK 关节位置误差和支撑期脚滑代理，逐序列报告改善和最差恶化。对不能由现有数据可靠计算的指标标记未验证，不造 proxy 成实机指标。
5. 确认集必须使用冻结的模型/门限一次运行。P6 只有在实际 P9 状态下短时 Swing 改善区间下界大于零、静态/零漂无损伤且 FK/脚滑指标不出现系统退化时，才保留为有证据的合成增量收益。FK/脚滑的非劣容差必须在看确认集前按骨架映射误差预先登记；若无法合理确定容差，则报告绝对差异并将该验收项标为未通过/未决。否则保留为研究假设，回到数据/目标审计，不扩容网络。

## 禁止事项与阶段安全

- 不启用 `applyCorrectionToTrackers()`，不覆写 Tracker、Skeleton 或 Avatar 姿态，不接入用户 VRChat 会话。
- 不将 smoke/random 权重的 ONNX 通过解释成模型精度通过。
- 不把 `Tracker.getAcceleration()` 线加速度写进契约的角加速度字段；不把全零角速度说成传感器读数。
- 不把 Phase 11 oracle 短时收益、合成的频域能量或任意合成噪声描述成实机证据。
- 不依赖被 `.gitignore` 排除且无法重建的模型文件作为唯一验收输入；报告记录本机模型哈希，必要 fixture 从源码可重建。
