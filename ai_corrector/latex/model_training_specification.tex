\begin{abstract}
本文件记录当前 SlimeVR 下肢姿态校正研究的实际架构和工程边界。研究方案由两个职责分离的分支构成：Phase 6（P6）多流因果 CSTN 从四个下肢 IMU 与 HMD/VD 上身参考中预测短时姿态残差；Phase 9（P9）为四颗下肢 tracker 分别维护慢变世界偏航误差状态。Phase 11 的 Swing--Twist 合成器先应用 P9 的世界偏航修正，再只保留 P6 残差的非偏航 Swing 分量，以减少分支串扰。
截至 Phase 12，P6 已导出 ONNX 并接入 SlimeVR 服务端影子推理；P9 估计器和 P6/P9 合成仍是 Python 原型与离线验证，尚未集成到 Kotlin 运行链路。服务端默认影子模式，当前没有在线姿态修正。现有数值来自合成数据，尚不能证明实机长期漂移收益、真实 VD 条件下的融合增益或足底滑移改善。
\end{abstract}

6D 旋转采用旋转矩阵前两列，避免欧拉角不连续；四元数 ABI 使用 \([w,x,y,z]\)。无效或缺失的胸部、手臂及腿部流以零值和无效标志表示。当前服务端对 HMD 要求有效；胸部和手臂位置使用相对 HMD 的坐标。年龄字段目前写为零，不能视为已完成时延估计。

模型训练的腿部加速度来自合成数据中的线加速度。服务端在同一字段写入 \texttt{Tracker.getAcceleration()}。训练角速度由仿真直接生成；运行时优先读取 tracker 角速度字段，字段不可用时再由连续姿态四元数差分推导。Phase 12 审计未发现实际生产代码写入原始 tracker 角速度的调用点，因此运行时角速度与合成训练输入存在链路差异。

\subsection{服务端采样位置}
服务端在所有 \texttt{Tracker.tick()} 之后、\texttt{HumanPoseManager.update()} 之前采样。桥接器刷新 tracker 绑定、拼装 124 维帧、执行 ONNX 推理并缓存候选残差、门控和触地概率。Reset 和 tracker 断连会清空因果状态。输入字段及 Kotlin 映射见 \texttt{CorrectorBridge.kt}、\texttt{CorrectorConfig.kt} 与 \texttt{OnnxCorrectorEngine.kt}。

\section{P6：短时多流因果 CSTN}

\subsection{网络结构}
每个输入流独立嵌入到 96 维：线性层、LayerNorm、LeakyReLU。8 路嵌入分别进入一个单层因果 LSTM（hidden size 96），每路维护独立的 \(h,c\) 状态。每帧将 8 个 LSTM token 送入 3 层、8 头的 Transformer Encoder，进行 tracker 之间的空间交互。Transformer 之后的 token 均值形成全局上下文；它只用于构造上下文特征，不会替代腿部专属 token。

每个腿部姿态头将该腿 token 与全局上下文拼接，经独立 MLP 输出 3 维旋转向量，再转成单位四元数残差。四个腿部各有独立姿态头和门控头。残差向量幅度受最大 8 度限制。触地头从全局上下文输出左右脚两个概率。具体结构见 \texttt{ai\_corrector/corrector/model.py}。

因果时间信息由逐流 LSTM 状态跨帧递推；Transformer 只在当前帧的 8 路 token 之间注意，不沿时间轴做全序列注意。运行时逐帧输入、连续传递状态。这提供时序记忆，但当前训练与验收没有证明它能可靠保留或估计 30 分钟尺度的偏航误差。

\subsection{Yaw-Neutral 姿态残差}
基础 CSTN 输出局部右乘残差 \(\delta q_{\mathrm{local}}\)。Yaw-Neutral 包装器使用输入中的原始姿态把该增量共轭到世界系，并绕世界竖直轴 \(Y\) 分解：
\[
\delta q_{\mathrm{world}}
=\delta q_{\mathrm{swing}}\otimes\delta q_{\mathrm{twist},Y}.
\]
输出只保留 Swing，并转换回局部右乘约定。世界 \(Y\) 轴 Twist 被丢弃，避免 P6 与慢偏航分支重复修正同一自由度。网络本身分别输出 Swing 残差和门控值；离线合成器在门控低于 0.3 时使用恒等修正，高于门限时按门控权重做 identity-to-correction SLERP。导出器输出四路局部 Swing 四元数、四路门控、双脚接触概率以及下一帧的递归状态。

\subsection{训练损失}
Phase 11 Yaw-Neutral CSTN 使用以下加权目标：
\[
\mathcal{L}
=10\mathcal{L}_{\mathrm{swing}}
+15\mathcal{L}_{\mathrm{twist}}
+\mathcal{L}_{\mathrm{gate}}
+\mathcal{L}_{\mathrm{contact}}.
\]
\(\mathcal{L}_{\mathrm{swing}}\) 监督非偏航姿态残差；\(\mathcal{L}_{\mathrm{twist}}\) 惩罚世界竖直轴扭转；门控与接触头使用二元交叉熵。序列 mask 忽略填充帧。损失和包装逻辑见 \texttt{yaw\_neutral\_cstn.py}。

\section{P9：每 tracker 独立的慢偏航状态估计}

\subsection{状态定义}
P9 为左/右大腿和左/右小腿分别维护：
\[
\mathbf{x}_i =
\begin{bmatrix} e_i \\ b_i \end{bmatrix},
\qquad \mathbf{P}_i\in\mathbb{R}^{2\times2}.
\]
其中 \(e_i\) 是世界竖直轴的偏航姿态误差，\(b_i\) 是该姿态误差的变化率；它不是直接读取的芯片原始陀螺零偏。预测阶段执行 \(e_i\leftarrow\operatorname{wrap}(e_i+b_i\Delta t)\)，并传播协方差；每路独立更新并限幅。原型对 reset 和较大时间跳变实现状态复位；掉线期间如何恢复状态仍需服务端级验证。

\subsection{候选观测器}
\begin{itemize}
  \item \textbf{静止段 ZARU：}逐 tracker 检查低角速度、短窗稳定性和姿态突变。达到持续静止时长后，从静止区间的姿态变化估计偏航变化率，向对应状态通道提供率观测和几何对齐信息。
  \item \textbf{直线步态锚点：}在 HMD/VD 参考有效、HMD 水平位移达到阈值且大腿具有周期性摆动时，比较大腿前向轴水平投影与 HMD 行进方向，产生低权重偏航角观测。转身、原地运动、非直线行走或角度差过大时拒绝更新。
  \item \textbf{状态滤波：}ZARU 主要约束偏航误差率 \(b_i\)，步态观测只更新偏航角 \(e_i\)，避免弱步态观测把角度噪声耦合到长期漂移率。
\end{itemize}
这些是 Python 原型的工作逻辑，不代表已经有经过实机标定的观测噪声或完整生产实现。代码见 \texttt{bias\_estimator\_v3.py} 和 \texttt{bias\_state\_v3.py}。人体可以长时间保持非标准静态姿势，单纯对姿态角做低通会把真实姿势当成漂移；P9 的设计因此尝试依赖静止段的姿态变化率和严格条件下的步态锚点，而不把静态姿态本身拉回某个“标准朝向”。

\section{Phase 11：P6/P9 正交融合算子}

对 tracker \(i\)，令输入原始姿态为 \(R_{\mathrm{raw},i}\)，P9 估计的偏航误差为 \(\hat e_i\)，P6 输出局部残差为 \(\delta R_{6,i}\)，门控为 \(g_i\)。离线合成流程如下：
\begin{align}
R_{9,i} &= R_y(-\hat e_i)R_{\mathrm{raw},i},\\
R_{6,\mathrm{cand},i} &= R_{9,i}\delta R_{6,i},\\
D_i &= R_{6,\mathrm{cand},i}R_{9,i}^{T}.
\end{align}
将 \(D_i\) 转成四元数并沿世界 \(Y\) 轴作 Swing--Twist 分解。令其 Swing 分量为 \(q_{\mathrm{swing},i}\)，丢弃 Twist 分量。若 \(g_i<0.3\)，令门控 Swing 为单位旋转；否则令
\[
q_{\mathrm{swing},i}^{g}
=\operatorname{SLERP}(1,q_{\mathrm{swing},i},g_i).
\]
最终姿态和服务端局部右乘等价增量为
\[
R_{\mathrm{out},i}=R(q_{\mathrm{swing},i}^{g})R_{9,i},
\qquad
\delta R_{\mathrm{server},i}=R_{\mathrm{raw},i}^{T}R_{\mathrm{out},i}.
\]
因此慢偏航修正来自 P9；P6 只能增加通过门控的 Swing 修正，其世界 \(Y\) Twist 不参与合成。合成器的实现与数值边界测试见 \texttt{hybrid\_composer.py} 和 \texttt{test\_h1\_orthogonal\_operator.py}。

\section{训练数据与适用边界}

\subsection{P6 数据}
训练以 AMASS 动作序列构建合成 tracker 流。Phase 11 数据生成器记录 796 条训练序列、150 条验证序列和 190 条 FinalConfirm 序列。下肢各路独立注入动作相关 Swing 扰动；Phase 11 使用的扰动轴和幅度由角速度启发式构造（包含 \(0.040\|\boldsymbol{\omega}\times\mathbf{u}\|\) 项），它不是从真实 SlimeVR AHRS 误差标定或重放得到。VD/HMD 参考在主要实验中接近理想 AMASS 观测，不能覆盖真实噪声、延迟、安装偏差与重定位。

数据按序列隔离，不代表受试者级隔离。Phase 12 对 A2 复用 Phase 11 的 190 条 FinalConfirm，因此 A2 数字只作为探索性结果，不能作为新的确认集通过。

\subsection{评测结果及解释}
\begin{itemize}
  \item Phase 11 合成 30 分钟会话中，P9 ZARU-only 的平均端点偏航净收益为 \(+141.7188^\circ\)，候选 P9+P6 为 \(+141.7191^\circ\)。两者几乎相同，未显示 P6 的额外长期偏航收益；结果来自 10 条合成会话，Phase 12 已判定 A1 门禁无效且观测链路不一致，不能视为实机收益。
  \item Phase 11 的 Swing 确认性分析以真值构造的 P9 oracle Twist 作基线，平均 Swing 残差由 \(2.1799^\circ\) 降至 \(0.7261^\circ\)，报告改善 \(66.7\%\)。扰动为合成启发式、上身参考理想，且该 190 序列后来在 Phase 12 A2 被复用。因此它只说明模型能改善该合成目标，不能代表在线 P9 条件或真实 VD/IMU 表现。
  \item Phase 12 A2 报告显示 P9-only 与 Raw 相同，P9+P6 与 P6-only 相同。旧 FinalConfirm 被复用、简化 FK/脚滑代理和未纳入最终门禁的压力条件，使 A2 被裁定为探索结果，未证明融合增益。
\end{itemize}

\section{ONNX 与 SlimeVR 服务端接入状态}

\subsection{模型 ABI 与时延}
ONNX Runtime 使用单帧张量 \(x\in\mathbb{R}^{1\times1\times124}\)，输入递归状态 \(h,c\in\mathbb{R}^{8\times1\times1\times96}\)，输出四路残差 \(dq\)、四路门控 \(\mathrm{gate}\)、双脚接触概率 \(\mathrm{contact}\) 以及下一帧状态 \(h_n,c_n\)。模型以 60 Hz 逐帧运行，CPU 单线程 ONNX Session 常驻。Phase 12 本机测试在 108,000 逻辑帧上逐帧推理；3,000 个组装加推理样本的 P95 为 0.6571 ms。该计时未覆盖完整 \texttt{VRServer.tick()}，也不等于完整端到端延迟。

\subsection{当前服务端行为}
\begin{enumerate}
  \item \texttt{CorrectorConfig} 默认为 \texttt{enabled=false}、\texttt{shadowMode=true}。影子模式运行推理并缓存候选输出，不修改骨架姿态。
  \item Kotlin 接入只实现 P6 ONNX 推理；没有调用 Python P9，也没有把 Phase 11 合成算子移植进服务端。
  \item 当前 \texttt{applyCorrectionToTrackers()} 只计算局部变量 \texttt{corrected}，没有将它写回 tracker 或骨架求解器。因此实际在线姿态修正路径尚未完成；不可将启用配置等同于完整模型已生效。
  \item ONNX 引擎实现了 \texttt{close()}，但 Phase 12 复核未发现 \texttt{VRServer} 关闭生命周期调用桥接器关闭方法；Session 资源释放仍待补齐。
\end{enumerate}
完整本机验证状态见 \texttt{public/phase-12-prehardware-validation/results.md}。13 项指定 Kotlin 测试通过，S2 回放逐帧推理和延迟结果通过其局部门槛；Phase 12 整体验收尚未通过。

\section{端到端软硬件流程清单与执行方案}
\label{sec:end_to_end_plan}

\subsection{系统链路总览}
项目有两条在服务端汇合的实时观测链，以及一条离线训练/验证链：
\begin{enumerate}
  \item \textbf{下肢惯性链：}四颗下肢 IMU（左/右大腿、左/右小腿）采集角速度和加速度；固件中的姿态融合（当前设计为 VQF）生成 tracker 姿态，经无线接收与 SlimeVR tracker 数据路径进入 Server。芯片具备原始陀螺仪并不代表 Server 已收到原始陀螺仪，必须沿固件、包结构、DataFeed 和 Tracker 更新路径逐段确认。
  \item \textbf{上身参考链：}HMD 及可用的 VD 上身虚拟 tracker 经 SteamVR/Feeder 进入同一个 Server。VD 输出按带质量、时延和丢失风险的辅助参考处理，不把胸部姿态当作下肢绝对偏航真值。
  \item \textbf{在线推理链：}Server tracker 更新 \(\to\) 时戳/坐标核验 \(\to\) 124 维特征 \(\to\) P6 ONNX 与 P9 状态估计 \(\to\) Phase 11 正交合成 \(\to\) 骨架求解输入 \(\to\) OpenVR 或 OSC/VMC 输出。
  \item \textbf{离线研发链：}AMASS 与（硬件到手后的）同步实测记录 \(\to\) 数据清洗和独立 manifest \(\to\) P6 训练、P9 参数标定 \(\to\) ONNX 导出/回放 \(\to\) 独立真值评测。训练真值和评测标签不得进入在线特征。
\end{enumerate}

本项目原型硬件规划包含 6 个 IMU 节点，但当前 124 维模型契约只消费四个下肢 IMU；其余身体参考由 HMD/VD tracker 通道提供。执行前必须冻结实际 tracker 位置映射，避免把硬件节点数误当成模型输入通道数。

\subsection{逐项流程清单}
以下步骤按前置依赖排序。每项列出当前状态、执行动作与退出条件；方括号状态用于后续逐项更新。

\begin{enumerate}
  \item \textbf{[冻结] 目标、分工与模型容量。}
  \begin{itemize}
    \item \textbf{输入/输出：}目标是一次 reset 后至少 30 分钟，四路下肢 tracker 开始到结束的累计偏航误差总量低于 Raw；P9 负责慢偏航，P6 负责短时 Swing。
    \item \textbf{执行：}冻结 P6 主干为当前 hidden size 96、8 路 LSTM、3 层/8 头空间 Transformer 和 joint-decoupled heads。当前阶段不增加参数量、不扩大网络、不以模型容量作为优先优化方向。改动先针对观测字段、P9 物理门禁、数据质量与融合实现。
    \item \textbf{退出条件：}所有后续报告分别给出四路/会话端点主指标、短时 Swing 指标、零漂静态安全指标；不以逐帧平均误差代替 30 分钟端点目标。
  \end{itemize}

  \item \textbf{[待硬件] 硬件身份、安装与机械标定。}
  \begin{itemize}
    \item \textbf{输入/输出：}四颗下肢 tracker、HMD、可用 VD 上身 tracker、无线接收器；输出设备清单、固件版本、传感器轴向、tracker 身体位置、安装方向和校准记录。
    \item \textbf{执行：}逐设备记录 IMU 型号/ID、采样率、板载姿态算法、固件 commit、电池与连接状态；固定绑带并记录传感器到肢段的安装矩阵。确认 SlimeVR 中两大腿、两小腿位置没有左右或上下错绑。
    \item \textbf{退出条件：}设备身份和轴向可复现；重戴后能通过明确校准恢复；安装滑动可从传感器漂移中单独标记。当前无目标实机，暂不能执行此项。
  \end{itemize}

  \item \textbf{[待硬件/先审代码] 固件、AHRS 与传输字段核验。}
  \begin{itemize}
    \item \textbf{输入/输出：}固件原始 IMU、板载融合姿态、加速度和无线数据包；输出一份逐字段的数据来源表，说明单位、坐标系、时间戳和滤波语义。
    \item \textbf{执行：}沿传感器驱动 \(\to\) VQF \(\to\) 无线包 \(\to\) Server 协议解析 \(\to\) Tracker 更新逐段追踪角速度、加速度、融合四元数和时间戳。缺少原始角速度时明确标为不可用或由姿态差分派生；不把线加速度冒充角加速度，也不把空字段当零漂观测。
    \item \textbf{退出条件：}每个模型输入字段都能追溯到有效来源，仿真与线上采用相同定义。硬件到手前可完成协议与源码审计，物理输出核验待实机。
  \end{itemize}

  \item \textbf{[部分完成] VD/SteamVR/SlimeVR tracker 映射与参考系。}
  \begin{itemize}
    \item \textbf{输入/输出：}HMD 和虚拟上身 tracker 的姿态、位置、速度、质量与状态；输出实际设备映射表及统一世界坐标定义。
    \item \textbf{执行：}确认 VD 哪些上身 tracker 能经 SteamVR/Feeder 到达 Server；逐项核验胸部、左右上臂/肩部的 position enum、坐标变换、有效状态和重定位行为。分别记录 tracker 缺失、遮挡、延迟和空间重置。
    \item \textbf{退出条件：}数据映射与坐标方向通过可重复姿态测试；VD 有效性和年龄字段反映真实状态。不得由“VD tracker 可用”推导“该 tracker 是零漂绝对真值”。
  \end{itemize}

  \item \textbf{[部分完成] 时间基准、特征 ABI 与输入金标。}
  \begin{itemize}
    \item \textbf{输入/输出：}异步 tracker 更新；输出带单调时间戳、明确派生角速度和缺失标志的 124 维帧。
    \item \textbf{执行：}当前桥接器按 Server tick 采样，不能据此认定多设备已做硬件时间戳同步；先接入/追踪可用时间戳，计算真实 age，明确定义迟到和重复帧策略。固定 124 维 ABI，Python/Kotlin 共用非对称哨兵 fixture，逐元素对比旋转 6D、单位、有效标志、缺失策略和递归状态。
    \item \textbf{退出条件：}固定 fixture 的 Python/Kotlin 每维一致；真实输入的时间年龄不再无依据写零；角速度来源在训练、推理和报告中保持同一语义。
  \end{itemize}

  \item \textbf{[待硬件] 原始数据采集与独立参考建立。}
  \begin{itemize}
    \item \textbf{输入/输出：}SlimeVR/VD 服务端观测与独立光学或等效姿态参考；输出不可变原始日志、时钟映射、校准说明及每段数据 manifest。
    \item \textbf{执行：}保持影子模式、不写入候选修正；采集站立、非中立静态姿势、直线行走、转身、蹲起、抬腿等动作，并采集至少一段 reset 后连续 30 分钟会话。记录断连、丢包、温度、佩戴移动和所有 reset；开始与结束参考须在再次 reset 前取得并同步。
    \item \textbf{退出条件：}能够由原始记录重放同一输入；开始/结束真值的参考误差和时钟误差有量化范围。没有独立参考时只可验链路，不能验补偿收益。
  \end{itemize}

  \item \textbf{[进行中/待新数据] 数据预处理、隔离与标签。}
  \begin{itemize}
    \item \textbf{输入/输出：}AMASS 合成数据和经许可的实测记录；输出版本化训练/验证/确认 manifest、特征张量与真值标签。
    \item \textbf{执行：}先按 source/subject/session 分组再切分，禁止重叠窗跨集合。合成器要分开模拟传感器固有零偏、随机游走、姿态融合输出误差、安装误差、VD 噪声/延迟/掉帧；实测段单独保留且不用于调参后的最终确认。标签区分世界 Y 偏航 Twist 与非偏航 Swing。
    \item \textbf{退出条件：}每个样本可追溯到源序列、扰动参数和生成代码版本；FinalConfirm 未被训练、选模或反复查看。没有新独立数据时，结果标作探索或数据受限。
  \end{itemize}

  \item \textbf{[需修复门禁] P9 四路慢偏航估计。}
  \begin{itemize}
    \item \textbf{输入/输出：}合法的 tracker 时序、静止/步态候选观测；输出每路 \((e_i,b_i,P_i)\) 及锚点接受/拒绝原因。
    \item \textbf{执行：}先修静态姿势零漂独立测试，确认无漂时不误拉姿态；使用角速度方差、加速度方差和姿态变化共同判断静止，并确认这些量实际参与代码门禁。步态检测增加路径直线度/转向拒绝、速度和周期性条件；对坐姿、盘腿、转身、抬腿和缺失 VD 做拒绝更新测试。随后用 30 分钟 endpoint loss、正负漂移、随机游走和不同静态姿势调状态噪声，不接触确认集。
    \item \textbf{退出条件：}静态和严格零漂门限自动计算且全会话通过；隔离集上四路 endpoint 的收益置信区间下界大于零且最差会话受限。当前 A1 静态门禁无效，旧 PASS 不接受。
  \end{itemize}

  \item \textbf{[容量冻结] P6 短时 Swing 模型训练和导出。}
  \begin{itemize}
    \item \textbf{输入/输出：}124 维因果帧、干净姿态目标和有效 mask；输出固定架构下的四路 Swing 残差、门控、接触概率及 ONNX。
    \item \textbf{执行：}维持现有网络参数规模。先验证合成扰动与真实 AHRS 误差的对应关系，再对不同动作、安装角、VD 延迟/缺失做数据增强；校准 gate 对“真实改善概率”的预测并分别检查零漂静态集。触地头只有在标签可复现且下游确实使用时才保留为有效任务。导出后检查模型哈希、ABI、逐帧递归状态和 PyTorch/ONNX 一致性。
    \item \textbf{退出条件：}新隔离集的短时 Swing 指标有统计收益，零漂/静态集不受损，gate 覆盖率和失效旁路达标；不以训练损失或 proxy F1 代替姿态收益。
  \end{itemize}

  \item \textbf{[离线已有/服务端待移植] P6/P9 正交融合。}
  \begin{itemize}
    \item \textbf{输入/输出：}原始腿部姿态、P9 的四路 \(\hat e_i\)、P6 Swing 残差和门控；输出经世界 Y Twist 投影的候选姿态。
    \item \textbf{执行：}先在 Python 对随机旋转、边界姿态、纯偏航输入、零门控和局部/世界坐标转换做属性测试；随后在 Kotlin 实现同一公式，以共享 fixture 逐元素比对。接入前分别运行 Raw、P9-only、P6-only、P9+P6 消融。
    \item \textbf{退出条件：}P6 不引入世界 Y Twist；门控为零严格回到 P9；P9 为零严格退化到 Yaw-Neutral P6；真实 P9 状态下的融合增益由全新隔离集确认。
  \end{itemize}

  \item \textbf{[影子原型/未完成] ONNX Runtime、状态与求解器写回。}
  \begin{itemize}
    \item \textbf{输入/输出：}通过 ABI 验证的 60 Hz 帧和模型；输出 shadow 诊断，再在安全门禁后形成送入骨架求解器的姿态。
    \item \textbf{执行：}维持默认 shadow-only；完成 Session 生命周期关闭、状态 reset、缺失/异常/超时旁路与完整 \texttt{VRServer.tick()} 回放。将 P9 与融合状态接入服务端后，设计单一、可回滚的 solver-input 写入点；防止反复累乘修正，原始 tracker 姿态始终保留用于对照。候选门控必须按验证过的 SLERP 权重执行。
    \item \textbf{退出条件：}无效模型或输入时逐帧等价于原生 SlimeVR；reset 后状态无泄漏；全链路延迟、内存上限和写入点均有自动测试。当前 \texttt{applyCorrectionToTrackers()} 未把结果写回，禁止视为可用在线修正。
  \end{itemize}

  \item \textbf{[待实机验收] SlimeVR 骨架、驱动输出与目标应用。}
  \begin{itemize}
    \item \textbf{输入/输出：}服务端骨架求解结果，经现有 OpenVR 驱动或 OSC/VMC 输出至 SteamVR/VRChat；同时保存原生与候选两路记录。
    \item \textbf{执行：}先检查 Avatar 骨架映射、左右腿方向、重置连续性和姿态边界；影子模式确认日志与实际输出不互相污染。在线开关只有在离线和实机影子门禁全部通过后再单独评审，不在本阶段默认启用。
    \item \textbf{退出条件：}原生输出可随时回滚；独立真值证明端点偏航改善，且站立/坐姿/动态动作的全姿态误改和最差会话不超预设门限。
  \end{itemize}
\end{enumerate}

\subsection{依赖顺序与当前可执行项}
\begin{enumerate}
  \item \textbf{现在可执行：}源码级字段映射审计；修复 P9 静止和步态检测门禁；完善静态姿势与零漂测试；统一角速度派生语义；更新 124D 哨兵测试；ONNX ABI、复位、异常旁路、Session 释放和完整服务循环回放；准备真实数据记录格式与隔离 manifest 模板。
  \item \textbf{硬件到手后先执行：}硬件身份/安装核验 \(\to\) 真实 tracker 映射和时间字段核验 \(\to\) shadow-only 短测 \(\to\) 多动作采集 \(\to\) 同步独立参考的 30 分钟会话。先验证信号来源与记录质量，再用数据决定训练和 P9 参数。
  \item \textbf{满足数据门禁后执行：}在固定 P6 容量下重建训练集；P9 使用开发集调参；冻结阈值和模型后只运行一次全新确认集；再把通过的 P9 和融合器接入 Kotlin 并重复回放。
  \item \textbf{上线门禁：}真实输入契约、零漂/静态安全、四路 30 分钟 endpoint 收益、融合增量、异常旁路、Session 生命周期和完整端到端时延均通过后，才评估非影子应用。任一独立真值或数据隔离条件缺失，则保持 shadow-only 并标记未决。
\end{enumerate}

模型门控只是候选可信度，不构成安全证明。短时 Swing 收益、慢偏航 endpoint 收益、全姿态误修改和脚滑诊断必须分别报告；不得以网络输出看起来平滑或延迟达标替代精度验收。
